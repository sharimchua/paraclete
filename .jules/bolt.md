## 2024-06-25 - [Optimize get_reference_usage database query]
**Learning:** Found an O(N) loop with N+1 query vulnerability in `get_reference_usage` where each reference evaluates lengths of `linked_notes` and `persons`. This requires the ORM to load all references into memory and potentially execute additional queries per reference to evaluate the counts if relationships aren't eagerly loaded.
**Action:** Replace Python-side O(N) iteration and counting with an optimized SQL query utilizing `func.count()`, `.group_by()` in subqueries, and `.outerjoin()` with `func.coalesce()` to perform the calculation entirely in the database engine, returning only the top 10 rows. This reduces memory usage drastically and executes extremely fast. I also verified the performance improvement with a script before committing.
